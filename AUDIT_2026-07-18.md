# Аудит Postmaker — 18 июля 2026

## Что улучшено сейчас

- Случайные темы теперь ведут отдельный постоянный журнал для каждого языка в `localStorage`. Тема попадает в журнал сразу после показа и не возвращается в последующих очередях. Ротация также чередует тематические направления, чтобы подряд не попадали похожие сюжеты.
- Выбор перевода Библии вынесен в отдельную кнопку рядом с языком. Доступные наборы зависят от активного языка и передаются в генератор текста как явное требование.
- Интерфейс desktop и mobile переведён на Liquid Glass: полупрозрачные слои, глубина, мягкие цветовые блики, контрастные CTA и более ясная фокусировка полей.

## Архитектура генерации

### Сильные стороны

- Есть локальный fallback для текста и изображения: приложение остаётся полезным при недоступности провайдера.
- Текстовый промпт уже различает стиль, угол регенерации, тему, стих, пасторский фокус и наличие эмодзи.
- Подбор стихов сначала работает локально, затем может усиливаться AI-поиском; карточки проходят проверку формата ссылки и дедупликацию.
- Для изображений есть очереди, retry и каскад бесплатных провайдеров; это снижает количество сырых ошибок пользователю.

### Следующий приоритет

1. **Каталог стихов по переводам.** Сейчас переключатель задаёт предпочтение генератору, а встроенная локальная библиотека содержит базовые формулировки. Для гарантированно дословного результата каждого перевода нужно подключить лицензированный/разрешённый источник и хранить для каждого стиха `translationId → text/reference`.
2. **Серверный журнал тем для нескольких устройств.** Текущий журнал намеренно остаётся на устройстве пользователя. Если уникальность должна соблюдаться между браузерами или участниками команды, нужна небольшая серверная таблица с `language`, нормализованной темой и датой выдачи.
3. **Версионность промптов и оценка качества.** Зафиксировать 30–50 эталонных тем на каждый язык и автоматически проверять: язык ответа, длину, пять хэштегов, наличие темы в первой строке, отсутствие повторов и соответствие выбранному переводу.
4. **Кэширование.** Кэшировать результаты подбора стихов на короткое время по `language + topic + matchMode`; это сократит задержку и обращения к модели при повторном редактировании.
5. **Изображение и текст — отдельные статусы.** Уже есть токены отмены рендера; следующим шагом стоит добавлять `requestId` и отмену HTTP-запроса через `AbortController`, чтобы быстрые смены настроек не тратили лишнюю квоту.
